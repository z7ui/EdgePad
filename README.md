# 边触 EdgePad

把三星 One Hand Operation+ 的思路搬到普通安卓上：屏幕左右各一条悬浮手柄，从手柄往里滑，执行你绑定的动作。

不联网、不申请存储权限，规则全在本机。

## 手势

每一侧 6 种：

| 方向 | 短滑 | 长滑 |
| :--- | :--- | :--- |
| 水平（往屏幕里） | ✓ | ✓ |
| 斜上 | ✓ | ✓ |
| 斜下 | ✓ | ✓ |

- 起点必须在手柄上，滑出去也算（触摸目标不会因为手指离开手柄而丢）
- 短滑与长滑的分界是屏高的 16%
- 方向判定：横向位移 ≥ 纵向位移 1.35 倍算水平，否则按上下分
- 往外滑（朝屏幕外）不触发，避免误触

## 动作（21 个）

| 分类 | 动作 |
| :--- | :--- |
| 导航 | 返回、回到主屏、最近任务、上一个应用 |
| 面板 | 通知面板、快捷设置、电源菜单 |
| 屏幕与工具 | 截屏、锁屏、手电筒、分屏 |
| 声音 | 音量 +、音量 −、静音、播放 / 暂停、下一首、上一首 |
| 应用 | 打开应用、搜索、语音助手、系统设置 |
| 其它 | 不绑定 |

「上一个应用」靠无障碍事件记住的包名历史，重新打开上一个应用，不保留页面状态。
「分屏」用 `FLAG_ACTIVITY_LAUNCH_ADJACENT` 把上一个应用并排打开，部分 ROM 会退化成普通启动。

## 权限

| 权限 | 用途 | 不给会怎样 |
| :--- | :--- | :--- |
| 悬浮窗（显示在其他应用上层） | 手柄本身 | 手柄不显示，应用等于没用 |
| 无障碍 | 返回 / 主屏 / 最近任务 / 通知栏 / 锁屏 / 截屏；记住前台包名 | 这几类动作无效，其余动作正常 |
| 通知 | 常驻通知与动作结果 | 常驻通知不显示，服务照跑 |

无障碍只订阅 `typeWindowStateChanged`，只读包名，不申请读取窗口内容，也不读界面文字。

## 手柄外观

宽度（8–32dp）、高度（20–90% 屏高）、离边缘距离（0–120dp）、透明度（10–100%）、垂直位置（−40%–40%）。
默认 16dp / 46% / 40dp / 42% / 0。

**离边缘默认是 40dp，这是有讲究的**：全面屏手势下，屏幕左右边缘约 20~30dp 是系统「返回」的地盘，
第三方应用的悬浮窗盖不掉（系统的 `GestureStub` 窗口压在上面）。实测贴边（8dp）时真实手指滑动
会被系统返回吃掉、根本到不了手柄；挪到 40dp 后才能稳定触发。所以默认取 40dp。
如果你改用三键导航（`settings put secure navigation_mode 0`），系统手势区消失，可以把离边缘调到 0 贴边使用。

## 应用例外

勾上的应用里，手柄隐藏、手势不生效。适合游戏、视频、输入法。

## 和 OHO+ 的差别

OHO+ 是三星系统签名应用，持有 `INJECT_EVENTS`、`INTERNAL_SYSTEM_WINDOW`、`STATUS_BAR_SERVICE` 这类权限，还能让系统导航手势让位。边触只有悬浮窗和无障碍，所以：

- 不能注入按键：菜单键、方向键、键盘组合键做不了
- 不能接管导航手势：只能靠往屏幕里缩来避让
- 不能改系统开关：Wi-Fi、蓝牙、飞行模式这些没做（要做得上 root）
- 单体动作数量 21 个，OHO+ 是 73 个；能对上的部分基本都在

完整的逐条对照见 [docs/OHO-对照.md](docs/OHO-对照.md)。

## 构建

```bash
./gradlew assembleDebug     # 调试包
./gradlew assembleRelease   # 正式包，签名读 keystore/keystore.properties
```

`keystore/` 不入库。缺这个目录时构建自动退回 debug 签名。

## 已知限制

- 只在小米 25098PN5AC（Android 16，KSU root）上测过
- 悬浮窗权限 MIUI 不允许脚本授予，必须手动开一次
- 手柄是普通悬浮窗，不是系统窗口：系统 UI 弹出时它可能被盖住
- 分屏、上一个应用的体验依赖 ROM，属于「尽力而为」
